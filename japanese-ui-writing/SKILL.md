# 日本語のUI文言

このskillのルールは、すべての製品の日本語UI文言に適用する必須仕様であり、デザインテストの合否基準として扱う。通知の表示方法、待機表示、配色、レイアウトなどのUI実装仕様は扱わない。

## 語彙

- 日本語のUI文言の説明には和語を使用せず、熟語とカタカナ語を使用する。ラベル、補足文、toast、エラー、ダイアログに共通適用する。
- 「やり直す」は「再試行」、「取り消す」は「取消」、「お知らせ」は「通知」と表記する。同一の操作・状態には同一の用語を使用する。
- 意味を維持して置換し、独自の略語や不必要な専門用語は追加しない。助詞・助動詞など、文法上必要な表現は使用できる。
- 固有名詞、引用、利用者の入力原文は一律に置換しない。
- 「受付済」「処理中」「確定」「完了」は区別し、実際の業務状態と一致する表現を使用する。受付済を確定、処理中を完了と表示しない。

## 句点と改行

- ラベル、補足文、toast、エラー、ダイアログでは、原則として句点「。」を付けない。
- 複数の文は句点でつなげず、文や意味の区切りで改行する。実際の画面でも改行が反映される要素や表示方法を使い、ソース内の改行だけで済ませない。

たとえば「削除します。この操作は取り消せません。」は、次のように表示する。

```text
削除実行
実行後の取消不可
```

句点を使う文章では、途中の文だけでなく最後の文にも付ける。スキルの説明文も同様に、文末の句点を揃える。

UI文言で句点を省くルールは、記事本文、規約、引用、利用者が入力した原文には一律に適用しない。

## 補足文は判断に必要な情報だけにする

自明な説明文のUI表示は禁止する。ラベル・操作部品・状態・数値から判断可能な内容の再説明は削除する。既存の説明文も検査対象とし、新規追加と同一の基準を適用する。

説明文の削除によって、入力条件・適用範囲・操作結果・失敗時の対処に関する情報が欠落するかを確認する。情報の欠落がなければ、その説明文は表示しない。必要な条件・影響の説明は維持する。

| やってはいけないこと | 解決策 |
| --- | --- |
| 「保存ボタンで保存」「検索欄から検索」「一覧で確認」など、自明な操作を説明する | 説明文を削除する。操作名・配置だけでは判断困難な場合は、ラベル・操作部品・配置を修正する。 |
| 「こちらで確認可能です」のように操作説明を重ねる | まずリンク名・ボタン名・配置を分かりやすくする。入力条件や公開範囲など、判断に必要な説明は残す。 |
| ラベル・ボタン・入力欄と同じ操作を、その下でも文章で説明する | 重複する補足を削除する。「分類を選択・入力」と表示する欄に「候補から選択、または自由に入力できます」を重ねない。 |
| 分かりにくい操作を、常設の「〜できます」「〜してください」で補う | 操作名・入力欄・配置を先に直す。入力欄のラベルは残し、プレースホルダーだけで項目名を示さない。 |
| 登録ボタンが見える空の一覧で、「このボタンから追加できます」と案内する | 空であることだけを伝える。操作への案内は、その場に必要な導線がない場合に置く。 |
| 添付済みのファイルや計算結果が見えているのに、同じ状態・計算を文章で繰り返す | 状態・数値はその表示に任せる。添付数の上限や現金の移動の有無など、表示から分からない条件だけを補足する。 |
| 同じ画面で、原本との照合などの手順を何度も説明する | 共通の案内は1か所にまとめる。読み取りを確認すべき項目の表示や、保存時の確認操作は残す。 |
| 添付済みでも「添付してください」と表示するなど、現在の状態と異なる案内を置く | 状態に応じて表示する。未添付時の必須条件と、添付後の状態表示を分ける。 |
| どのエラーにも「入力内容を確認」「時間をおいて再試行」などの定型文を足す | その失敗に合う対処だけを示す。再試行ボタンと同じ案内を繰り返さず、結果が不明な更新では記録の確認を案内する。 |
| 取得件数が少ない一覧や空の履歴にも、「最大1,000件」「直近100件」などの上限を常設する | 上限に達した場合など、取得範囲の説明が必要な状態で示す。総件数と取得件数が分かる場合は、それに合わせて表示する。 |
| 短くするために、必要な条件や影響まで削除する | ファイル形式・容量・件数、空欄の扱い、権限、変更が及ぶ範囲、取消の影響などは必要な箇所へ短く残す。情報が混ざる文は、重複部分だけを削る。 |

「全期間」「全サービスで共通」「在庫へ加算／入力数に置換」などは、見た目だけでは分からない仕様として扱う。文末が「できます」であることだけを理由に削除しない。

## 変更後の確認

変更した文言を実際の画面と状態で確認する。語彙が熟語・カタカナ語で統一され、自明な説明文・不要な句点・重複説明がなく、改行が表示に反映され、入力条件・適用範囲・操作結果・失敗時の対処が失われていないことを確認する。画面の状態が変わった後も文言が一致するかを確認する。

不適合は修正して再確認し、確認できた範囲、未確認の範囲、未解消の不適合を分けて報告する。
