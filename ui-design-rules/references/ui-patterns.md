# UIの実装・確認パターン

以下のルールは、スピナーや削除色を含め、すべての製品の必須仕様とする。変更対象に関係する節を読み、各ルールをデザインテストの合否基準として確認する。既存のデザインシステムや共通部品も、この仕様を満たすように整える。対象の操作や状態が存在しない項目は適用対象外とし、未実装や不適合を適用対象外として扱わない。

## 処理中・エラー表示

| やってはいけないこと | 解決策 |
| --- | --- |
| 「準備中…」「生成中…」などの進捗文言や、内部のステータス値をそのまま画面に出す | 処理中はスピナーを表示する。PDF生成だけに限らず、非同期処理の待機表示に適用する。 |
| ボタンのラベルを進捗文言に置き換え、処理段階ごとに表示を変える | ボタン内のラベルを一時的に隠し、同じ位置にスピナーを表示する。完了後は元のラベルへ戻す。 |
| ラベルを消した結果、ボタンの幅や周囲の配置が変わる | 元のラベルの領域を残し、処理中もボタンの寸法を保つ |
| 処理中も同じ操作を繰り返し実行できる | 対象のボタンを無効にし、処理終了時に再び操作できるようにする |
| スピナーだけを置き、読み上げでは何が起きているか分からなくする | 操作の名前と `aria-busy` を設定し、開始・終了の通知には視覚的に隠した `role="status"` などを使う。名前や `aria-busy` の変更だけで通知されるとは限らないため、読み上げでも確認する。 |
| 処理に失敗してもスピナーを表示し続ける、またはエラーまで隠す | 待機表示を解除し、失敗したことと再試行などの対処方法を文章で伝える |
| 動きを減らす設定でもローダーやスピナーを動かし続ける | `prefers-reduced-motion: reduce` に対応し、全画面ローダーを省略してスピナーの回転を止める |

- スピナーへ置き換えるのは待機中の表示。「購読を開始しました」などの操作結果はtoastで伝える。「学内限定」などの公開範囲、入力項目ごとのエラーや空の一覧の説明は該当箇所に残す。

### 操作結果の通知はtoastに統一する

| やってはいけないこと | 解決策 |
| --- | --- |
| 保存・削除・送信などの成功や失敗を、インラインの通知バーやメッセージで表示する | すべての製品で共通のtoastを使う。同じ操作結果をインラインにも重複表示しない。 |
| 画面ごとにtoastの位置・見た目・表示方法を変える | 共通部品を使い、成功・失敗の表現と表示位置を揃える。操作中の要素やフォーカス枠を隠さない。 |
| toastへフォーカスを強制移動する、読み上げで通知されない | 操作中のフォーカスを保ち、成功は `role="status"`、即時に伝える必要がある失敗は `role="alert"` などで通知する。同じ結果を複数の読み上げ領域から重複通知しない。 |
| 対処が必要な失敗のtoastを自動で消す | 利用者が閉じるまで残し、何に失敗し、次に何ができるかを示す。toast内の閉じる・再試行などはキーボードでも操作できるようにする。 |
| 同一操作のtoastを複数表示する、再描画・再接続で連続通知する | 1操作につき1通知とする。同一事象は共通IDで既存のtoastを更新する。 |
| 成功・案内のtoastが残り続ける、確認中に自動終了する | 成功・案内は約5秒で自動終了し、ホバー・フォーカス中は終了タイマーを停止する。エラー・要確認は手動終了まで維持する。 |
| toastの終了後に再試行・結果確認が不可能になる | toastに再試行・結果確認のアクションを用意し、終了後も画面の操作から再実行・確認できるようにする。 |

入力項目ごとのエラーは、修正箇所を特定するために項目の近くへ表示する。空・取得失敗・権限不足などの継続する状態説明も該当領域に残す。これらは操作結果の通知と区別し、toastだけに置き換えない。

### 待機・失敗・空の状態

| やってはいけないこと | 解決策 |
| --- | --- |
| 一部分の処理でページ全体をローダーに覆い、読める本文まで隠す | 対象のボタンや領域だけを待機表示にする。本文の表示を画像・フォント・外部APIの完了待ちにしない。 |
| JavaScriptが動かなければ全画面ローダーが消えない | 通常は本文を読める状態にし、スクリプトの失敗時にも覆いを残さない。PDF生成などJavaScriptが必要な操作には、その操作に限って説明を出す。 |
| 通信が終わらないままスピナーを回し続ける | 処理に応じた時間制限を設け、待機解除後の対処方法を示す。初期化などの結果が不明な操作は、自動で再実行せず状態を確認する。 |
| データ取得の失敗を「0件」「まだありません」と表示する | 未取得・取得失敗・取得成功で0件を区別する。失敗した領域に説明と利用できる代替導線を置く。 |
| 入力エラーをtoastだけで伝え、入力欄から離す | 入力エラーは該当項目の近くに表示し、再入力が必要な箇所を示す。送信失敗などの操作結果を通知する場合は共通のtoastを使う。 |
| 内部エラーコードや例外メッセージを、利用者向け説明としてそのまま出す | 何に失敗し、次に何ができるかを日本語で伝える。技術的な詳細は通常表示から分ける。 |
| 取得失敗によって既存データを消去する | 既存データを維持し、最新データの取得失敗と再取得操作をtoastで通知する。 |
| 未登録と検索・絞込結果0件を同一の状態として表示する | データ未登録と検索・絞込結果0件を区別する。検索・絞込結果0件には条件クリアを用意する。 |

### 検証・保存・競合

| やってはいけないこと | 解決策 |
| --- | --- |
| 初回入力中から検証エラーを表示する、不正項目の修正後もエラーを維持する | 初回検証は送信時に実行する。不正と判定した項目は修正中にも再評価する。 |
| APIの成功確認前に成功通知・一覧更新・フォーム終了を実行する | APIの成功確認後に成功通知と一覧更新を実行する。保存後に終了するフォームは、その後に終了する。 |
| 競合時に入力を破棄する、旧データで上書きする、同一更新を自動再送する | 入力内容を維持し、最新状態の確認へ誘導する。旧データによる上書きと同一更新の自動再送は禁止する。 |
| 接続成功や再接続を保存成功として通知する | 接続状態と保存状態を区別する。再接続後は最新状態を確認し、保存結果を確認してから通知する。 |
| 一括操作の対象範囲や部分失敗の内訳を不明確にする | 選択範囲と件数を明示する。部分失敗時は成功件数・失敗対象をtoastで通知し、失敗分の確認・再操作の導線を用意する。 |

根拠：[W3Cの状態通知の解説](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)、[入力エラーの特定](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html)。

## 操作と導線

| やってはいけないこと | 解決策 |
| --- | --- |
| JavaScript標準の `alert()`・`confirm()` で確認操作を済ませる | 既存の共通ダイアログで対象と結果を示す |
| ボタンやリンクのフォーカスを見えなくする | キーボード操作時にフォーカス枠を表示する |
| 白文字のボタンに明るいアクセント色を使い、文字を読みにくくする | 既存の `--color-button-primary` など、ボタン専用の色を使う |
| 削除系の単独ボタンを通常色で表示する、選択メニューの一項目を赤い塗りで強調しすぎる | 保存済みデータ・画像の削除や解除、記録の取消、入力行・選択ファイルの削除、未保存変更の破棄は、単独ボタンと確認ダイアログでは赤背景・白文字に統一する。選択メニュー内は赤文字と控えめなホバー背景で示し、赤い塗りのボタンにはしない。単独ボタンはライト・ダーク、ホバー・フォーカス・処理中・無効状態でも白文字を保つ。通常のキャンセル・閉じる・チェックボックスの選択解除は中立色にする。 |

### ラベル・フォーム・確認操作

| やってはいけないこと | 解決策 |
| --- | --- |
| 画面遷移も処理の実行も、クリック可能な `div` で実装する | 遷移には `a href`、処理には `button` を使い、キーボードでも操作できるようにする |
| 「こちら」「詳しく」や矢印だけで操作を示す | 「諸則の一覧に戻る」「PDFをダウンロード」など、操作結果や移動先が分かる名前にする。装飾用の矢印は読み上げ対象から外す。 |
| 同じ領域で複数のボタンを同じ強さで強調する | 主な操作を1つに定め、補助操作は副ボタンやテキストリンクにする |
| プレースホルダーだけを入力欄の名前にする | 入力しても消えないラベルを付ける。形式や制限は項目の近くに置き、必要に応じて `aria-describedby` で関連付ける。 |
| 入力エラーを赤枠だけで伝える、送信失敗で入力内容を消す | 問題と直し方を文章で示し、`aria-invalid` などで項目と関連付ける。再試行に必要な入力内容は保つ。 |
| 無効なボタンを薄くするだけで、使えない理由を伝えない | 選択や必須入力などの条件を近くに示す。無効状態でも操作名は読めるようにする。 |
| 削除・初期化を確認なしで実行する、確認画面の初期フォーカスを実行ボタンに置く | 対象と結果を確認画面に明記し、初期フォーカスはキャンセル側など安全な位置に置く |
| 実行前の確認画面をキーボードで閉じられない、閉じるとフォーカスが迷子になる | `dialog` などを使い、内部でのTab移動、Escapeでの閉鎖、閉じた後の呼び出し元への復帰を確認する。処理中の閉鎖と処理の取消は別に扱う。 |
| ダイアログ表示中に背面のページをスクロールできる | 表示中はページのスクロールを固定する。長い内容はダイアログ内だけでスクロールし、閉じた後は元の位置から操作を再開できるようにする。確認画面などを重ねた場合も、最後の画面を閉じるまで背面の固定を解除しない。 |
| 未保存の変更を確認なしで破棄する | 終了前に破棄確認を表示する。編集続行時は入力内容を維持する。 |
| 中断不能な送信中にダイアログを終了できる | 閉鎖操作・Escape・外側クリックによる終了を抑止する。タイムアウト後は結果確認へ移行する。 |
| 呼び出し元の消失によってフォーカスの復帰先がなくなる | 一覧見出しなど、次の操作に適した位置へフォーカスを復帰する。 |
| 削除確認で対象・件数・影響を省略する、復元可能な操作を取消不可と表示する | 対象名・件数と連動する影響を明示する。取消不可の説明は復元不能な操作に限定する。 |


## 装飾と情報の階層

| やってはいけないこと | 解決策 |
| --- | --- |
| `ACT-01` のような番号や、見出しの上の英字ラベルを装飾として繰り返す | 見出し自体と文字サイズ、余白で区切る。諸則の条番号や「学内限定」などの意味がある表示は残す。 |
| 日本語見出しを `ch` 基準の狭い幅へ押し込み、不自然に何行も折り返す | 日本語の文字幅に合う `em` などで幅を取り、スマートフォンでも文字切れしないようにする |
| 短い操作ラベルが途中で折れる、長い操作ラベルが画面からはみ出す | 短いラベルは1行を基本とし、長いPDF操作などは必要に応じて折り返す |

### 内容と情報の保持

| やってはいけないこと | 解決策 |
| --- | --- |
| 最初の画面を抽象的なコピーだけにして、誰の何のサイトか分からなくする | 運営主体、提供内容、主な移動先を最初の画面で把握できるようにする |
| 装飾を削った後の空白を、巨大な余白や意味のないカードで埋める | セクションの高さと配置を内容に合わせる。必要な説明や実際の制作物を読みやすく示す。 |
| ページを充実させるために、活動実績・人数・推薦文・GitHubの数値を作る | CMSや取得できた実データだけを使う。取得できない数値を0として補わない。 |
| 見出しをすべて2行に収めるため、正式な文書名やCMSの記事名を省略する | 長い名称は折り返して読めるようにする。短く編集できる見出しと、保持すべき正式名称を区別する。 |

## 日時の表示

- 日跨ぎは開始日時と終了日時を表示し、終了日を省略しない。年跨ぎは開始・終了の両年を表示する。
- 締切は相対時間だけで表示せず、絶対日時とタイムゾーンを明示する。製品の日時仕様と一致させる。

## モバイル・キーボード・読みやすさ

| やってはいけないこと | 解決策 |
| --- | --- |
| ホバーしたときだけ操作や情報が現れる | タッチ操作でも必要な情報と操作を見つけられるようにし、キーボードのフォーカス時にも示す |
| アイコンの見た目だけを小さなタップ領域にする | ボタンの押せる範囲と間隔を確保する。独立した主要操作は44×44 CSS pxを目安にし、本文中のリンクには一律適用しない。 |
| 閉じたモバイルナビゲーションのリンクへTabで移動できる | 非表示時は `inert` や `hidden` で操作対象から外す。開閉状態を `aria-expanded` と一致させる。 |
| メニューを開いたまま本文へフォーカスが移る、Escapeで閉じた後にフォーカスを失う | 通常のナビゲーションはフォーカスが外れたら閉じるなどの扱いを定める。Escapeで閉じる場合は開閉ボタンへ戻す。モーダルとして作る場合は背景操作を無効にする。 |
| 固定ヘッダーやトーストが、フォーカス中の操作を隠す | 重なりとスクロール位置を調整し、操作対象とフォーカス枠を見える位置に保つ |
| 文字がはみ出した部分を `overflow-x: clip` で隠すだけにする | 長い見出しやURL、拡大表示で折り返しを確認する。表やコードなど幅が必要な部分だけ、領域内でスクロールさせる。 |
| 色の違いだけでエラー・選択・公開範囲を区別する | 文字、形、選択状態を併用する。色を見分けなくても意味が伝わるようにする。 |
| 補足文字を薄く小さくし、読めなくする | 実際の背景とのコントラストを確認する。通常の文字は4.5:1、大きな文字は3:1以上を基準にし、拡大しても読めるようにする。 |

44pxは操作性の目安。WCAG 2.2のターゲットサイズの最低基準は24pxで、間隔や本文内リンクなどの例外がある。[ターゲットサイズ](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

根拠：[ナビゲーションの開閉](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/)、[フォーカスの遮蔽](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)、[リフロー](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[色の使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)、[コントラスト](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
